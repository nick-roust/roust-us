# Data model: unresolved

No derived data model or JSON Schema is approved or implemented. This document records research questions only; it contains no banking fixtures or sample records.

Before proposing a model, establish from authoritative sources:

- Which entities, identifiers and relationships the applicable ED807 version defines.
- Which fields are mandatory, optional, repeated or conditionally present.
- How to preserve original textual identifiers, dates, encoding and code values without loss.
- How absent values, unknown codes, historical entries and status changes should be represented.
- How a full publication differs from incremental updates, and how effective dates should be interpreted.
- What source metadata and validation diagnostics derived records need.
- Whether the website needs a complete dataset, a subset or no published data, subject to verified redistribution terms.

An implementation proposal must cite research evidence, state unresolved ambiguities and define failure behavior. Do not infer a contract from a single file or fabricate JSON examples in advance.
